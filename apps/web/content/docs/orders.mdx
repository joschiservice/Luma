---
title: Work with orders
description: Find an order, see what still needs work, and check the source facts behind it.
---

Orders lists every current order Luma has read from your connected stores and ERPs. Orders imported from different systems start as separate records. After you link them as the same order, Luma shows one order and keeps each system’s facts separate.

## Find an order

Search by order number, the order's ID in its source system, SKU text on an order line or a source SKU ID. Combine search with filters for status, payment, source and placed date, and sort by last update, placed date, order number or due date. Each filter is always shown next to the search: choose one, such as **Status**, to pick a value. An applied filter shows its value, which you can change or remove. The placed date offers today, the last 7 or 30 days, or a custom range. On a phone, choose **Filters** to see every filter at once.

The views narrow the list to work that matters:

- **Outstanding** shows open orders with units still to fulfill.
- **Overdue** shows outstanding orders past the deadline their source reported.
- **Needs you** shows orders linked to an issue that needs a decision or review.
- **Differs by source** shows orders whose status, payment, total or ordered items disagree between systems.

Outstanding, overdue and needs you count the same orders as the order metrics on Insights. Choosing a metric there opens the matching view here.

Every filter, sort and page is part of the address, so you can share it or pin it to the sidebar.

## Read an order

**Current state** explains the order in a few sentences: its status and payment, how many units are still to fulfill, whether it is overdue, and which issues need you. Luma bases it on the source with the newest update and names any system that disagrees.

**Lines** shows ordered, cancelled, fulfilled and remaining quantities per item. When a source does not report cancelled quantities, remaining work is shown as unknown instead of guessed.

**Source comparison** lines up each system's facts side by side. Order numbers and dates are shown but not compared, because each system assigns its own.

**Observed history** lists each state Luma read from a source. It shows what the source reported at that time, not every change the source made.

For Shopify orders, the Shopify details section reads payments, customer, fulfillment holds, returns, refunds and source events live from your store. Customer details appear only when your Shopify app is approved for protected customer data.

## Link source orders

Open an order’s **Linked sources** panel. Owners and admins can link an imported Shopify
order to its JTL sales order. Suggestions use JTL’s external order number; they are never
applied automatically. Dates and totals help you review a match. If several orders share
that reference, check each source record before choosing.

Choose **Link**, compare the source IDs, dates and totals, then explain why they represent
the same order. Without a suggestion, use **Find another order** and **Review link**.
Luma shows progress while it applies the request. Once complete, both source versions appear
on this order, with separate lines and shipments. Old order links open the combined order;
existing issues, activity and observed history remain reachable.

To separate them again, choose **Unlink** beside a source and give a reason. That source
becomes its own order with its lines and shipments. Every link and unlink records who
requested it and why. Linking does not change either provider’s records.

## Act on an order

Open a linked issue to review it, open a workflow run to see its steps, or follow an item to its stock and product. **Copy link** copies the order's address for a colleague.

## Recover a held fulfillment

In an order’s **Shopify details**, open a **Fulfillment order**. Owners and admins
can release one hold, reopen fulfillment or move all remaining items to an
eligible location. The recovery panel explains when Shopify does not allow an
action or the connection needs fulfillment write access.

Choose the exact hold or destination and select **Preview recovery**. Another
administrator must open the same fulfillment and approve the change. The
requester can then select **Run approved action**. Previews expire after ten
minutes; changes in Shopify require a new review.

**Shopify accepted** confirms the request was accepted. **Progress verified**
means a later Shopify read showed fewer unfulfilled items. Select **Check
fulfillment progress** to read again. If acceptance is uncertain, Luma will not
resend the action. Review the order in Shopify and reconcile the existing
recovery before starting another.
